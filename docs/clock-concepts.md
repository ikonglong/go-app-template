## 1. 缘起：一个时刻，两种数字

排查 go-apperror 伪版本 `v0.0.0-20260518085823-4fc551345f1c` 时间戳时发现，同一个
提交时刻能显示成两个不同的数字：

- `16:58:23 +0800` —— 提交者**本地时区的墙钟读数**
- `08:58:23 UTC` —— **同一时刻**的 UTC 墙钟读数

它们是同一个瞬间的不同时区呈现，都属于「墙钟」。伪版本时间戳取的是 UTC 那个。

由此引出三组概念，下面逐一厘清。

## 3. 轴一：墙钟 vs 单调钟（读数的种类）

这是**最重要**的一组区分，和时区无关，讲的是「这个时间值是哪一种」。

| | 墙钟 wall clock | 单调钟 monotonic clock |
|---|---|---|
| 是什么 | 日历/民用时间，挂钟读数 | 自某起点（如开机）持续递增的计数 |
| 绑时区？ | 是 | 否（纯计数，谈时区无意义） |
| 会跳变？ | **会** —— NTP 校正、夏令时、手动改表、闰秒 | **不会**，永不回拨 |
| 用途 | 时间戳、日志、「**何时**发生」 | 测量**时长 / 流逝**（「过了**多久**」） |
| 例子 | git 提交时间、伪版本时间戳 | `time.Since(start)` 背后用的就是它 |

### Go 里它俩同居一个 `time.Time`

`time.Now()` 返回的 `time.Time` **同时携带**一份墙钟读数和一份单调钟读数：

- **相减测时长** —— 若两个值都带单调读数，`t2.Sub(t1)` / `time.Since(t1)` 自动用
  **单调**部分，结果不受期间 NTP/夏令时跳变影响；
- **格式化/显示/取年月日时分** —— 用**墙钟**部分。

⚠️ 一些操作会**剥掉单调读数**（之后相减就退化成墙钟相减）：`t.Round(0)`、
`t.Truncate(0)`、`t.AddDate(...)`、`t.UTC()`、`t.Local()`、`t.In(loc)`，以及任何
序列化（`Format` / JSON 都不保留单调部分）。`t.Round(0)` 是惯用的「显式剥离」写法。

## 4. 轴二：墙钟 vs `IClock`（值/源 vs 抽象）

第三组区分：把「墙钟」这个**真实时间源**和本项目的 **`IClock` 抽象**分开。

```go
// internal/common/clock/clock.go
type IClock interface {
	Now() time.Time
}

type RealClock struct{}

func (RealClock) Now() time.Time { return time.Now().UTC() }
```

- **wall clock** 是概念：真实世界此刻的时间。
- **`IClock`** 是一个 seam（接口）：它回答「时间**从哪来**」。把它注入（而非到处直接
  调 `time.Now`），是为了让接收 `time.Time` 的 domain 工厂在测试里**确定性可控**
  （注入固定时间的假 Clock）。
- **`RealClock`** 是生产实现：`time.Now().UTC()` ≈「读真实墙钟 → 转 UTC」。

> 一句话关系：**`IClock` 是「时间来源」的抽象；wall clock 是它在生产背后那个具体的
> 真实源。** `RealClock.Now()` 就是「把真实墙钟读出来、归一到 UTC」。

## 5. 本项目的取舍与一条实用提醒

`RealClock.Now()` 里的 `.UTC()` 有两层意图，也带一个**副作用**：

- ✅ **意图**：时间戳归一到 UTC，存库/打日志不受部署时区影响 —— 这是「**现在几点、
  打时间戳**」的墙钟用途，正是 `IClock` 的设计目标。
- ⚠️ **副作用**：`.UTC()` 会**剥掉单调读数**（见 §3）。所以 `IClock`：
  - **不适合测耗时**。若有人拿 `clock.Now()` 取两次相减算耗时，因为没有单调读数，会
    退化成墙钟相减；一旦期间发生 NTP/夏令时跳变，结果会偏、甚至为负。

**规则**：

| 你要做的事 | 用什么 |
|---|---|
| 取「当前时刻」做时间戳、记录「何时发生」 | `IClock.Now()`（注入,可测） |
| 测「过了多久」/ 耗时 / 超时 | 直接 `time.Now()` + `time.Since`（保留单调读数），**不要**走 `IClock` |

> 若将来确实要可注入地测耗时，应另设一个**单调时钟抽象**（如 `Stopwatch` / 返回带
> 单调读数的源），而不是复用这个 `.UTC()` 过的 `IClock`。

## 6. 速查

- **本地墙钟** = local wall clock；它显示的值 = wall-clock time（civil time）。
- **本地墙钟 vs UTC 墙钟**：同一时刻、不同时区呈现 —— 都是墙钟（时区轴）。
- **墙钟 vs 单调钟**：墙钟会跳变、用于「何时」；单调钟只增不减、用于「多久」（种类轴）。
  Go 的 `time.Now()` 两者都带；`.UTC()`/`.Round(0)` 等会剥掉单调部分。
- **墙钟 vs `IClock`**：前者是真实时间源/值，后者是「时间从哪来」的可注入抽象；
  `RealClock.Now()` = 读墙钟再转 UTC。
- **本项目**：`IClock` 专司「时间戳/何时」（wall，UTC 归一）；**测耗时用 `time.Since`**。
